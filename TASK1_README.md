# Task 1: Inductive Bias and Feature Representation

This README documents Task 1 of ATML PA1. The task compares frozen ResNet-50, ViT-B/16, and OpenCLIP ViT-B/32 visual representations on STL-10. Each frozen backbone is evaluated with a trained ten-class linear head, and CLIP is additionally evaluated through zero-shot classification.

The evaluation covers clean images, colour interventions, spatial translations, patch shuffling, and AdaIN cue-conflict images. The notebook also measures feature cosine similarity and produces t-SNE visualizations.

## Reproducing the experiment

Run Task 1 from the root `PA1/` directory:

```bash
jupyter notebook task1.ipynb
```

Run the notebook cells from top to bottom. The notebook is stateful, so later evaluation cells depend on objects created by earlier cells.

The main workflow is:

1. Set seed 6304 and select CUDA or CPU.
2. Download STL-10.
3. Create a stratified 4,000/1,000 training-validation split.
4. Create a balanced 500-image test subset containing 50 images per class.
5. Load and freeze the three pretrained backbones.
6. Extract training and validation representations.
7. Train one linear head per backbone.
8. Evaluate clean, grayscale, hue-rotated, translated, and patch-shuffled images.
9. Load and evaluate the manually reviewed cue-conflict set.
10. Save metrics, predictions, feature-similarity records, and figures under `results/`.

## Cue-conflict reproducibility and manual review

The cue-conflict dataset contains five unordered class pairs evaluated in both directions:

- airplane--monkey
- car--deer
- ship--cat
- truck--horse
- bird--dog

Candidate images were generated using AdaIN and manually reviewed. An image was rejected when the content object was no longer recognizable, the intended style change was not visible, severe artifacts obscured the object, or the output was blank or corrupted.

The notebook contains the following safeguard:

```python
REBUILD_CUE_CONFLICT_ASSETS = False
```

Keep this value set to `False` when inspecting the reported evaluation. This prevents the candidate set and manually tagged review workbook from being regenerated or overwritten.

The original reviewed cue-conflict run used the following local artifacts:

```text
results/cue_conflicts/candidate_manifest.csv
results/cue_conflicts/cue_conflict_review.xlsx
results/cue_conflicts/cue_conflict_review_tagged_backup.xlsx
results/cue_conflicts/final_cue_conflict_manifest.csv
results/cue_conflicts/candidates/
```

The lightweight GitHub submission retains the machine-readable results required to trace the reported metrics but does not include the full candidate-image directory or manual-review workbooks. Therefore, the reported cue-conflict metrics can be inspected from the committed outputs, but exact re-execution of the reviewed cue-conflict evaluation requires the original preserved review assets.

Set `REBUILD_CUE_CONFLICT_ASSETS = True` only when intentionally generating and manually reviewing a new cue-conflict dataset. A newly reviewed dataset may not reproduce the reported cue-conflict results exactly.

The manifests were produced on Windows and may contain Windows-style path separators. When using preserved manifests on Linux or macOS, normalize path columns from `\` to `/` before loading the images.

## Reproducibility notes

- Python, NumPy, PyTorch, CUDA, DataLoader shuffling, patch permutation, and t-SNE use seed 6304 where applicable.
- Training, validation, and test identities are retained alongside extracted representations and checked for cross-model alignment.
- The selected test subset is stored in `data/test_subset_seed6304.csv`.
- Transformations are applied to the same balanced test images for all models.
- Cue-conflict generation is separated from evaluation through saved images and manifests.
- Small CSV result files are committed so reported values can be traced to machine-readable outputs.
- Raw STL-10 data, cached pretrained weights, environments, and unnecessary checkpoints are not committed.
- Exact numerical equality across different PyTorch, CUDA, GPU, and operating-system versions is not guaranteed, although the fixed seeds keep the experimental protocol consistent.

## Known limitations and reporting decisions

The submitted notebook and saved outputs are retained as used for the report. The following issues were identified after the experiments and are documented rather than corrected because changing model construction or evaluation selection would require rerunning affected experiments and could change the reported results.

### OpenCLIP QuickGELU configuration

The notebook first loads the OpenAI-pretrained `ViT-B-32-quickgelu` configuration, but a later model-loading cell replaces it with `ViT-B-32` while still requesting the OpenAI weights. OpenCLIP emits a warning that the pretrained tag expects QuickGELU while the final model configuration has `quick_gelu=False`.

Consequently, the stored CLIP results were produced with this activation/configuration mismatch and should be interpreted as results for the exact submitted implementation rather than as a definitive evaluation of the canonical OpenAI CLIP ViT-B/32 configuration.

### Patch-grid reporting

The notebook evaluates patch grids of `1 x 1`, `2 x 2`, `4 x 4`, `8 x 8`, and `16 x 16`.

The report and compact comparison table use the `4 x 4` condition. However, `final_task1_summary.csv`, `final_accuracy_comparison.png`, and the patch-shuffle t-SNE section use the last/maximum evaluated grid, `16 x 16`.

Therefore, these outputs are not directly interchangeable. The grid-size column in the detailed patch CSV files is the authoritative way to select a condition:

```text
results/patch_shuffle_results.csv
results/patch_shuffle_feature_similarity.csv
```

### Metric availability differs by intervention

Accuracy, macro-F1, and confidence are available for the clean, colour, and cue-conflict evaluations.

Translation and patch-shuffle tables primarily store accuracy and clean-to-intervention prediction consistency, with representation cosine similarity saved separately. The absence of macro-F1 or confidence for these two intervention families should not be interpreted as a zero value.

### Stateful notebook and saved outputs

The notebook is exploratory and stateful rather than a clean single-run pipeline. It contains repeated setup and analysis cells, and its final compact-table cell was rerun after a kernel restart.

Run order therefore matters, and rerunning isolated cells can use objects left by earlier cells. For exact report values, use the committed CSV outputs and, where applicable, the original preserved cue-conflict assets rather than assuming every displayed output came from one uninterrupted top-to-bottom execution.

### Scope of reproducibility

Fixed seeds, saved split identities, alignment checks, and preserved cue-conflict manifests support protocol-level reproducibility.

They do not remove the effects of the CLIP configuration issue, manual cue-conflict selection, software-version differences, GPU nondeterminism, or the patch-grid selection differences described above.
